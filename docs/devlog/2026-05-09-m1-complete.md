## 遇到的问题与解决

### 1. 包名错认：`dart_fsrs` 不存在
**现象**：`flutter pub get` 报错"could not find package dart_fsrs"。
**原因**：pub.dev 上的实际包名是 `fsrs`（github 仓库才叫 `dart-fsrs`）。
**解决**：pubspec.yaml 中改用 `fsrs: ^2.0.1`，同步更新 spec 与 plan 文档。

### 2. `flutter_markdown` 已废弃
**现象**：`flutter pub get` 提示 `flutter_markdown` discontinued, replaced by `flutter_markdown_plus`。
**解决**：换为 `flutter_markdown_plus: ^1.0.7`。

### 3. `isNull` 命名冲突
**现象**：测试文件中 `expect(value, isNull)` 报错 'isNull' imported from both drift and matcher。
**解决**：先用 `import 'package:drift/drift.dart' hide isNull;`；后来发现根本不需要直接 import drift（drift 类通过 `database.dart` transitively 可用），直接移除该 import。

### 4. Android 构建失败：插件版本要求
**现象**：`flutter build apk` 报多个错：
- `sqlite3_flutter_libs` 要 minSdk 24
- `flutter_tts` 要 compileSdk 36 + 新 NDK
- Kotlin stdlib 2.2.x 与 Kotlin gradle plugin 1.8.22 不兼容

**解决**：修改 `android/app/build.gradle.kts`：
- `minSdk = 24`
- `compileSdk = 36`
- `ndkVersion = "27.0.12077973"`

修改 `android/settings.gradle.kts`：
- Kotlin gradle plugin `1.8.22` → `2.1.0`

这是真机调试 task 才会暴露的问题。属于"真实开发的代价"，plan 不可能预料具体版本号。

### 5. Flutter create 的模板 widget_test
**现象**：`flutter analyze` 报 `MyApp` not a class（因为模板的 widget_test 引用了被删的 main.dart 中的 MyApp）。
**解决**：把 widget_test.dart 删除从 Task 13 提前到 Task 11 一并清理。

## 反思与心得

1. **AI 协助下时间压缩比预期还高**。原估 9 小时的工作 ~1.5 小时完成。但其中 ~30% 时间花在"环境兼容问题"上，这部分 AI 帮不上太多忙，主要靠真机错误反馈定位。
2. **plan 中的版本号会过时**。pubspec.yaml 里写的版本号都是写 plan 时的猜测，与 pub.dev 现状有偏差。下次写 plan 可以**先 `flutter pub add` 解析最新兼容版本，再写入 plan**，能避免改三次。
3. **Flutter 真机适配真的有坑**。Huawei + Android 16 + 多个 plugin 共同要求版本升级，三处不同的配置文件都要改。这种事情 plan 提前定义不到，必须真机调出来。
4. **TDD 在 schema 这种"无业务逻辑"的层级，价值在于"快速验证 schema 没拼错字段"**，而不是真正驱动设计。这类测试写一次保留即可，未来 schema 演化时跑一下能立刻发现问题。
